क्लाइंट रोल्स और एक्सेस

आपकी संस्था में सामान्यतः एक Client Admin और जरूरत अनुसार Client Staff होते हैं। Client Admin एक्सेस, फाइनल अप्रूवल और जवाबदेही संभालता है। Staff के लिए अलग-अलग अकाउंट रखें।

महत्वपूर्ण: एक ही अकाउंट कई ऑपरेटर्स के बीच साझा न करें।

पहली बार ऑनबोर्डिंग

  3. प्रोडक्शन से पहले mandatory output fields लॉक करें।
  4. फुल बैच से पहले 20 से 50 रिकॉर्ड का पायलट रन करें।
  5. पूरा फ्लो validate करें: Pending से Verified से Approved से Download।
  6. एक SOP फाइनल करके सभी बैच में वही पैटर्न रखें।

Quick Start in 8 Steps

1

Login to your dashboard and confirm your client name in the header.

2

Open ID Card Group and choose the correct table for your class or batch.

3

Upload card data and images in the required format.

4

Review records in Pending and fix invalid details before verify.

5

Move clean records to Verified after checking text, photo, and class section.

6

Approve cards only after final proof-check from your reviewer.

7

Download final outputs from approved or download status.

8

Track updates daily from dashboard activity and notifications.

Client Roles and Access

Your organization usually has one client admin and optional client staff users. Client admin controls access, final approvals, and accountability. Staff should use individual accounts with minimum required permissions.

Important: Never share one account across multiple operators.

First-Time Onboarding

  1. Assign named owners for upload, review, and final approval.
  2. Define one naming standard for groups and tables for the full session.
  3. Finalize mandatory output fields before production.
  4. Run a pilot with 20 to 50 records before full batch.
  5. Validate complete cycle: Pending to Verified to Approved to Download.
  6. Freeze SOP and reuse same pattern for all future batches.

दैनिक वर्कफ़्लो

डैशबोर्ड आपका कंट्रोल सेंटर है। स्टेटस काउंटर्स और एक्टिविटी फीड देखकर तय करें कि टीम को किस काम पर फोकस करना है।

  • Pending रिकॉर्ड्स पहले साफ करें ताकि बैकलॉग न बढ़े।
  • Verified को लंबे समय तक होल्ड न रखें, इसे review queue की तरह चलाएं।
  • Notifications को सिर्फ सूचना नहीं, action item मानकर काम करें।

Groups और Tables रणनीति

  1. Group को session या operational cycle के हिसाब से बनाएं।
  2. Table naming pattern फिक्स रखें, जैसे SchoolCode-Class-Section-Session-BatchNo.
  3. Production में रिकॉर्ड आने के बाद table rename कम से कम करें।
  4. हर table का owner तय करें ताकि जवाबदेही स्पष्ट रहे।

डेटा और इमेज अपलोड स्टैंडर्ड

आइटम न्यूनतम स्टैंडर्ड क्यों जरूरी है
Student Identifier सभी फाइलों में यूनिक और स्थिर गलत मैपिंग और डुप्लिकेट से बचाव
Name Fields अपलोड से पहले अंतिम स्पेलिंग फाइनल लेट-स्टेज करेक्शन कम होते हैं
Class और Section हर रो में एक जैसा फॉर्मेट फ़िल्टर और एक्सपोर्ट सटीक रहते हैं
Photo Files एक ही naming pattern अपलोड mismatch errors कम होते हैं
{% else %}

Daily Workflow

The dashboard is your control center. Use status counters and activity feed to decide where the team should focus.

  • Pending should be processed first to avoid accumulation.
  • Verified should remain a review queue, not a long-term storage state.
  • Notifications should be treated as action items.

Groups and Tables Strategy

  1. Create group by session or operational cycle.
  2. Create table names with strict pattern, for example SchoolCode-Class-Section-Session-BatchNo.
  3. Avoid frequent renaming after records are in production.
  4. Assign ownership table-wise for accountability.

Data and Image Upload Standards

Item Minimum Standard Why It Matters
Student Identifier Unique and stable in all files Avoids wrong mapping and duplicates
Name Fields Final approved spelling Reduces late-stage corrections
Class and Section Single format for all rows Improves filtering and exports
Photo Files One naming pattern Reduces upload mismatch failures

स्टेटस वर्कफ़्लो और अप्रूवल क्वालिटी गेट

स्टेटस उद्देश्य जिम्मेदार
Pending प्रारंभिक सुधार और क्लीनअप Data Operator
Verified रिव्यू पूरा, साइन-ऑफ की प्रतीक्षा Reviewer
Approved फाइनल आउटपुट के लिए तैयार रिकॉर्ड्स Client Admin
Downloaded डिलीवरी ट्रैकिंग स्टेज Client Admin या Operator
जल्दी के लिए Pending से सीधे Approved न करें। इससे रीप्रिंट लोड बढ़ता है।

Approve करने से पहले चेकलिस्ट

  • नाम, क्लास और सेक्शन source records से मेल खाते हों।
  • फोटो स्पष्ट, centered, upright और सही छात्र की हो।
  • ID नंबर में कोई अंक missing या extra न हो।
  • Mandatory fields खाली न हों।
  • उसी टेबल में duplicate card न हो।

सुझाव: हर टेबल के लिए एक reviewer sign-off के बाद ही final approval करें।

{% else %}

Status Workflow and Approval Quality Gate

Status Purpose Owner
Pending Initial correction and cleanup Data Operator
Verified Review-complete, waiting sign-off Reviewer
Approved Final output-ready records Client Admin
Downloaded Delivery tracking stage Client Admin or operator
Do not skip directly from Pending to Approved for speed. It increases reprint load.

Checklist Before Approve

  • Name, class, and section are correct and consistent with source records.
  • Photo is clear, centered, upright, and belongs to the correct student.
  • ID number has no missing or extra digits.
  • Mandatory fields are not blank.
  • No duplicate card exists in the same table.

Recommendation: each table should have one named reviewer sign-off before approval.

एक्सपोर्ट, डिलीवरी और रीप्रिंट हैंडलिंग

Export और Delivery प्रोटोकॉल

  1. Delivery stage के अनुसार Approved या Download स्टेटस फ़िल्टर करें।
  2. आवश्यक फॉर्मेट में export करें और बार-बार क्लिक से बचें।
  3. बड़े जॉब्स में background task पूरा होने दें।
  4. प्रिंटर या स्कूल को भेजने से पहले sample verify करें।
  5. ट्रेसेबिलिटी के लिए standard naming के साथ archive रखें।

रीप्रिंट और Exception Handling

  • रीप्रिंट केवल valid correction केस में ही करें।
  • हर रीप्रिंट के लिए reason note रिकॉर्ड करें।
  • रीप्रिंट के बाद final delivery से पहले card पुनः verify करें।
  • Repeated reprints को ट्रैक करें ताकि root cause निकाला जा सके।
Export bundles के लिए सुझाया नाम: Client-Table-Date-Format-Operator.

Exports, Delivery, and Reprint Handling

Export and Delivery Protocol

  1. Filter by Approved or Download status per delivery stage.
  2. Export in required format and avoid repeated trigger clicks.
  3. For large jobs, wait for background task completion.
  4. Verify a sample before sharing to printer or school authority.
  5. Archive files with strict naming convention for traceability.

Reprint and Exception Handling

  • Use reprint only for valid correction scenarios.
  • Capture reason note for every reprint.
  • After reprint, revalidate card before final delivery.
  • Track repeated reprints to identify root quality issues.
Suggested filename for exported bundles: Client-Table-Date-Format-Operator.

Recommended Role Matrix

Role Main Work Approval Rights
Data Operator Upload and correction in pending queue No

Security Basics

  • Disable inactive staff immediately.
  • Review permissions every week during active season.
  • Keep source upload files backed up before bulk changes.
